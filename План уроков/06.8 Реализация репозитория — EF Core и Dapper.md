# Реализация репозитория локации 

## Обзор

В проекте реализованы две реализации репозитория локаций:
1. **EF Core** - через Entity Framework Core
2. **Dapper** - через Dapper + Npgsql

Обе реализации находятся в проекте `TemplateService.Infrastructure.Postgres` и реализуют контракт `ILocationRepository` из `TemplateService.Core`. 

## Переключение между реализациями

Для переключения между реализациями используйте настройку `LocationRepositoryType` в `appsettings.Development.json`

```json
{
    "LocationRepositoryType": "EfCore" // или "Dapper"
}
```

Также можно задать через переменную окружения: 
```bash
set LocationRepositoryType=Dapper
```

## API для создания локации 

### POST /api/locations

**Запрос:**

```json
{
  "name": "Москва Сити",
  "address": {
    "street": "Пресненская наб., д. 12",
    "city": "Москва",
    "zipCode": "123317",
    "country": "Россия"
  }
}

**Ответ при успехе (201 Created):**

```json
{
  "id": "3fa85f64-5717-4562-b3fc-2c963f66afab",
  "name": "Москва Сити",
  "address": {
    "street": "Пресненская наб., д. 12",
    "city": "Москва",
    "zipCode": "123317",
    "country": "Россия"
  },
  "createdAt": "2026-07-11T10:00:00Z",
  "updatedAt": "2026-07-11T10:00:00Z"
}

**Ответ при дубликате имени (409 Conflict):**
```json
{
  "status": 409,
  "title": "Имя локации уже занято",
  "detail": "Локация с именем 'Москва Сити' уже существует."
}
```

## Сценарии тестирования

### 1. Создание новой локации (EF Core)

1. Установите `LocationRepositoryType: "EfCore"` в appsettings.Development.json
2.	Запустите	приложение: `dotnet run --project	backend/TemplateService/src/TemplateService.Web`
3.	Отправьте	POST запрос на `/api/locations`
4.	Проверьте	ответ (должен вернуть 201 Created	с id)
5. Проверьте таблицу `directory.locations` в PostgreSQL

### 2. Создание новой локации (Dapper)

1. Установите `LocationRepositoryType: "Dapper"` в appsettings.Development.json
2. Перезапустите приложение
3.	Отправьте	POST запрос на `/api/locations` с	новым	именем
4.	Проверьте	ответ (должен вернуть 201 Created	с id)
5. Проверьте таблицу `directory.locations` в PostgreSQL

### 3. Проверка уникальности имени

1. Отправьте повторный POST запрос с тем же именем локации
2. Должен вернуться ответ 409 Conflict
3. Ошибка обрабатывается на уровне бизнес-правила (проверка перед записью)

## Обработка ошибок

При ошибке сохранения в БД:
- Ошибка дотируется через `ILogger` с использованием `LoggerMessage`
- Выбрасывается `InfrastructureException` с контекстной информацией
- В будущих версиях будет добавлен Result-подход и Exception Middleware

## Структура файлов

```
TemplateService.Infrastructure.Postgres/
├── LocationRepository.cs           # Реализация через EF Core
├── DapperLocationRepository.cs     # Реализация через Dapper
├── LocationRepositoryType.cs       # Enum для выбора реализации
├── InfrastructureException.cs      # Исключение инфраструктуры
├── DependencyInjection.cs          # Метод расширения для DI
├── TemplateServiceDbContext.cs     # EF Core DbContext
└── Configurations/
    └── LocationConfiguration.cs    # Конфигурация EF Core для Location
```

## Миграции БД

Для применения миграций EF Core выполните: 
```bash
dotnet ef database update --project backend/TemplateService/src/TemplateService.Infrastructure.Postgres --startup-project backend/TemplateService/src/TemplateService.Web
```

## Connection String

По умолчанию используется:
```
Host=localhost;Port=5432;Database=template_service;Username=postgres;Password=postgres
```

Измените в `appsettings.Development.json` при необходимости.
