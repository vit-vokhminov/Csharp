Result-подход, Exception Middleware и структурированное логирование пока не подключаем. Здесь достаточно минимально зафиксировать ошибку сохранения в логах, чтобы упавший запрос не исчезал молча.

Бизнес-требование
Создание локации должно стать первой полностью рабочей фичей Directory Service. Админ отправляет POST /locations, получает id новой локации, а в PostgreSQL появляется строка. Повторный запрос с тем же именем должен отбиваться правилом уникальности до записи в БД.

Что нужно сделать
Две реализации репозитория локаций — сделай реализацию контракта через EF Core и вторую через Dapper + Npgsql. Обе должны вести себя одинаково с точки зрения Application/Core.

Одинаковые сценарии в обеих реализациях — добавление новой локации и проверка занятости имени. В EF Core используй возможности DbContext, в Dapper — явный SQL-запрос.

Минимальная обработка ошибки сохранения — если запись в БД падает, ошибка должна попасть в лог. Result-подход и middleware придут позже, поэтому сейчас не нужно строить полноценную систему ошибок.

Переключение реализации — приложение должно запускаться с одной из двух реализаций репозитория. Способ переключения выбери простой: главное, чтобы можно было быстро прогнать один и тот же сценарий через EF Core и через Dapper.

Проверка полной цепочки — запусти сервис, создай локацию через API, проверь строку в PostgreSQL и повтори сценарий для второй реализации. Повтор с тем же именем должен останавливаться на бизнес-правиле уникальности.

Что должно быть готово
В инфраструктурном слое есть две реализации репозитория локаций: EF Core и Dapper + Npgsql.
Обе реализации умеют добавить локацию и проверить занятость имени.
Ошибка сохранения логируется и не проходит молча.
Приложение запускается с выбранной реализацией; переключение на вторую не требует переписывать Application/Core.
POST /locations с валидными данными возвращает id, а psql показывает новую строку в таблице локаций.
Повторный POST /locations с тем же именем не создаёт дубль и останавливается на проверке уникальности.
Сценарий создания и сценарий дубля воспроизводятся с обеими реализациями.
